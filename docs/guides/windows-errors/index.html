Windows Event Viewer errors: which ones matter, and where to start

The System log is full of red and yellow. A handful of entries explain crashes, restarts and black screens. The rest is noise.

By Marcin Firmuga·Published 2026-11-27·6 min read

You open Event Viewer because the PC restarted in a game, or the screen went black for a second, and the System log is a wall of errors. Most of them are harmless and appear on every Windows PC. Four sources explain most crashes, restarts and black screens on a gaming PC: Kernel-Power, nvlddmkm, Display and WHEA-Logger. This page tells you which one you are looking at, how serious it is, and which guide walks you through it.

How to find them in Event Viewer

  1. Press Win + X and choose Event Viewer.
  2. Open Windows Logs → System.
  3. On the right, click Filter Current Log and type 41,153,4101,17,18,19,47 into the Event IDs box.
  4. Sort by Date and Time and look at the minutes just before the moment it happened. The event that matters is usually the one right before the restart, not the red one after it.

Three questions do more than any single entry: when did it start (after a driver update, a new part, XMP), how often does it repeat, and what was the PC doing at that minute (a game, a render, idle).

Short answers

Is Kernel-Power 41 dangerous?

It is a symptom, not a cause. Windows writes Event 41 when it starts again after it did not shut down cleanly. The fields BugcheckCode and PowerButtonTimestamp tell you whether it was a blue screen, a hard hang or a sudden loss of power.

What does nvlddmkm Event 153 mean?

The NVIDIA graphics driver was reset after the graphics card stopped responding for about two seconds (Timeout Detection and Recovery). One a month is noise; several a day under load point at the driver, an overclock, heat or power.

Which WHEA-Logger event is serious?

Events 17, 19 and 47 are errors the hardware corrected, so they matter by how often they appear. Event 18 is a fatal hardware error that could not be corrected.

Can I ignore DistributedCOM 10016?

Yes. Microsoft states that these events can be safely ignored because they do not affect functionality and are by design.
