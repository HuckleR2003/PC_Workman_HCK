Windows · Errors and crashes

Your PC freezes for a few seconds, then carries on. Here is how to find out why.

The mouse stops, the sound stutters, the game hangs, and three seconds later everything is fine. That pattern has four usual causes, and each one leaves a different trace.

By Marcin Firmuga·Published 2026-11-27·10 min read
Short answer

A freeze that recovers by itself means something held the whole system for a moment. Usually one of four things: a drive that stopped answering, a driver keeping the CPU busy (high DPC latency), memory running out, or the graphics card hanging. Do not change settings yet. First catch which one:

  1. Note the time of a freeze, and what you were doing (game, desktop, waking from sleep).
  2. Open Event Viewer at that minute: disk 153, storage 129, Display 4101.
  3. If sound crackles or the mouse stutters, run LatencyMon for 10–15 minutes; it names the driver.
  4. Watch disk response time and hard faults in Resource Monitor while it happens.
  5. Then fix the one cause the evidence points at.

Four causes, four signatures

What you noticeLikely causeWhere it shows
Everything waits, the drive light stays on, programs say "Not responding" and then wake upStorage stopped answering and was retriedEvent Viewer: disk 153, storahci / stornvme 129 ("Reset to device"); high disk response time
Sound crackles or cuts out, the mouse skips, short hitches even at idleA driver holding the CPU (DPC latency)LatencyMon names the driver: often network, graphics, storage or ACPI
Freezes when many programs or browser tabs are open, RAM near 90% or moreMemory running out, Windows reads from diskResource Monitor: hard faults per second jump; high RAM usage
In games, the picture freezes or goes black, then comes back or the game closesThe graphics card hangs and the driver is resetDisplay 4101, nvlddmkm 153, AMD driver timeout, LiveKernelEvent 141

Waking from sleep is its own case: users report a stall of a few seconds right after resume, often tied to a driver that is slow to wake or to Fast Startup. Test with Fast Startup off before anything else if your freezes only happen after sleep.

Read the minute in Event Viewer

  1. Win + X, Event Viewer, Windows Logs → System.
  2. Filter Current Log by 153,129,4101,41 and look at the minute of the freeze.
  3. Check the source, not only the number. disk 153 means "the IO operation … was retried": a storage request failed and Windows tried again, usually after a reset. nvlddmkm 153 is the graphics driver being reset. Same number, different problem.
  4. 129 from storahci, stornvme or storport ("Reset to device, \Device\RaidPort0, was issued") means the storage driver timed out a request and reset the device. That reset is your freeze.

Reliability Monitor (perfmon /rel) gives the same day in one view, with any LiveKernelEvent entries.

DPC latency: when a driver holds the CPU

Drivers do part of their work in Deferred Procedure Calls (DPCs), which run ahead of normal programs. That is fine when each one is short. When one driver's DPC runs for milliseconds at a time, audio buffers run dry (crackling), the mouse cursor skips, and the whole PC feels like it stutters, even with low CPU use in Task Manager.

LatencyMon from Resplendence measures exactly this: it shows the longest DPC and interrupt times and the driver file responsible. Run it, use the PC normally for 10–15 minutes until a freeze happens, then open the Drivers tab sorted by highest execution time. Common names:

  • ndis.sys, tcpip.sys or a Wi-Fi driver: the network adapter driver.
  • nvlddmkm.sys, amdkmdag.sys, dxgkrnl.sys: graphics.
  • storport.sys, stornvme.sys, storahci.sys: storage.
  • ACPI.sys, Wdf01000.sys, HDAudBus.sys: power management, a generic driver framework, or audio, which point you at the device behind them rather than at Windows itself.

If it ever ends in a blue screen, that is DPC_WATCHDOG_VIOLATION (0x133, BugcheckCode 307): the same driver delay, long enough that Windows stopped. See the BugcheckCode decoder.

Measure it while it happens

  • Resource Monitor (resmon), Disk tab: Response Time (ms) per file. Hundreds or thousands of milliseconds on the system drive during a freeze point at storage.
  • Resource Monitor, Memory tab: Hard Faults/sec. A jump into the hundreds or thousands while RAM is nearly full means Windows is reading from disk instead of memory.
  • Task Manager, Performance, Disk: Average response time. The percentage on that page measures time, not speed (why disk 100% misleads).

Fix by cause

  1. Storage. Check the drive's health (how to read it). Update the SSD firmware with the maker's tool, install the chipset and storage drivers from your motherboard's page, and for SATA drives try another cable and port. A drive that keeps producing 153 and 129 needs a backup before anything else.
  2. A driver (DPC). Update or roll back the driver LatencyMon named, from the device maker, not a driver updater. For network drivers, the adapter maker's driver often behaves better than the generic one. Update the motherboard BIOS if a newer one mentions stability or latency.
  3. Memory. Close what you do not need, find what grows over time (a memory leak shows as a program whose RAM only goes up), and keep a page file on an SSD. If freezes come whenever RAM is full during normal use, more RAM is the real fix.
  4. Graphics. Follow the graphics hang guide: defaults first, a clean driver, then heat and power.
  5. After sleep only. Turn off Fast Startup (Control Panel, Power Options, "Choose what the power buttons do") and test for a few days.

What not to do

  • Do not change ten things at once. If the freezes stop, you will not know why, and you will not know what to undo.
  • Do not install a "PC booster" or registry cleaner. None of the four causes is in the registry.
  • Do not ignore disk 153 and 129. They are the only early warning some drives give.

Short answers

Why does my PC freeze for a few seconds and then come back?

Something held the system for a moment: a drive that stopped answering, a driver keeping the CPU busy, memory running out, or the graphics card hanging. Each leaves a different trace.

What is DPC latency?

Drivers finish work in Deferred Procedure Calls that run ahead of programs. When one runs too long, sound crackles and the PC stutters. LatencyMon measures it and names the driver.

Is disk Event 153 the same as nvlddmkm 153?

No. disk 153 is a storage request that was retried; nvlddmkm 153 is the NVIDIA driver being reset.

Can a failing SSD cause short freezes?

Yes. Look for disk 153 and storage 129 at the minute of the freeze, and check the drive's health.
