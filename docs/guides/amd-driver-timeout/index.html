"AMD Software has detected a driver timeout": what it means, and what to check first

Your Radeon card went quiet for about two seconds and Windows restarted its driver. The pop-up is the least useful part of what happened.

By Marcin Firmuga·Published 2026-11-27·8 min read
Short answer

The message means the graphics card stopped responding within Windows' limit, 2 seconds by default, and Windows reset the AMD driver. It is the same mechanism as nvlddmkm Event 153 on NVIDIA cards. A single timeout after a driver update is common. Repeating timeouts have a cause you can find in this order:

  1. Reset GPU tuning in Adrenalin to defaults, including automatic undervolt and overclock.
  2. Clean-install the AMD driver (AMD Cleanup Utility, then the current Adrenalin), or go back one version if it started after an update.
  3. Test with XMP or EXPO off and without overlays and recorders.
  4. Watch temperature, hotspot and power under load.
  5. Still happening at defaults? Test the card in another PC.

What actually happened

Windows expects the graphics card to answer its scheduler quickly. When the card does not respond within the limit, Windows runs Timeout Detection and Recovery (TDR): it resets the graphics driver instead of freezing the whole PC. Microsoft sets that limit with the TdrDelay value, 2 seconds by default.

On a Radeon card, the AMD Software then shows "AMD Software has detected that a driver timeout has occurred on your system" and offers to send a bug report. What you saw before it, a black screen, a frozen game, a game that closed, was the hang. The pop-up is the receipt.

What Windows logs at the same moment

  • Event Viewer, System log: Display, Event 4101, "Display driver … stopped responding and has successfully recovered", usually naming the AMD kernel driver.
  • Reliability Monitor (perfmon /rel): often a LiveKernelEvent 117 or 141 at the same minute, with a dump in C:\Windows\LiveKernelReports\WATCHDOG.
  • If the whole PC restarted instead, it is no longer a timeout: read Kernel-Power 41.

Write down the time of each pop-up for a week. Same game every time, or random? Only under load, or also on the desktop and in the browser? That pattern decides where you start.

Common causes, most likely first

  1. Unstable tuning. A manual overclock, an undervolt, or automatic tuning presets in Adrenalin that are stable in one game and not in another. This is the first suspect when the timeouts appear under load.
  2. The driver version. Graphics drivers ship with bugs for specific cards and games, and AMD has released updates that fix driver timeouts for some cards. If it started right after an update, the update is a suspect; if you are on an old driver, a new one may contain the fix.
  3. Heat. A card that times out only after long gaming sessions, with a high hotspot temperature, points at cooling: dust, a failing fan, dried thermal paste.
  4. Power. Sudden load spikes on a weak power supply, or one split cable feeding two PCIe connectors.
  5. Unstable memory. XMP or EXPO profiles that are almost stable can take the graphics driver down with them.
  6. Software that hooks into games or the desktop. Overlays, recorders, RGB utilities, and browser hardware acceleration when the timeouts happen while watching video.
  7. The card itself. Last, after everything above has been ruled out.

A safe order to find the cause

One change at a time, then the same game for the same length of time. A step that changes nothing is information too.

  1. Defaults in Adrenalin. Performance → Tuning: reset GPU, VRAM and fan tuning to default, and turn off automatic overclock and undervolt presets for the test.
  2. Clean driver install. Run AMD Cleanup Utility (or DDU in Safe Mode), restart, install the current Adrenalin driver from AMD. If the problem began after an update, install the previous version instead and check whether it stops.
  3. Memory and the rest of the system at defaults. Turn off XMP or EXPO and any CPU overclock for the test. Make sure Windows has a page file; running without one is a known source of driver trouble.
  4. Overlays and hardware acceleration. Close recorders, overlays and RGB tools. If the timeouts happen in the browser, turn off its hardware acceleration and see whether they stop.
  5. Temperature and power under load. Watch the GPU temperature, hotspot and board power for 20–30 minutes of the game that fails. Use a separate cable from the power supply for each PCIe connector.
  6. The card. Still timing out at defaults, with a clean driver, normal temperatures and stable memory? Test the card in another PC, or another card in yours. If the fault follows the card, it is a warranty case.

What not to do

  • Do not stop at turning off Issue Reporting. It removes the pop-up. The driver still resets and Windows still logs it.
  • Do not raise TdrDelay as the fix. Microsoft documents the TDR registry keys for testing and debugging during driver development. A longer wait hides the reset and keeps the hang.
  • Do not buy a driver updater or "repair" tool. Several pages that rank for this error sell one. AMD's own driver and cleanup tool are free.

Short answers

What does "AMD Software has detected that a driver timeout has occurred" mean?

The card did not respond within Windows' limit, 2 seconds by default, so Windows reset the AMD driver. It is the AMD side of the same mechanism behind nvlddmkm Event 153 on NVIDIA cards.

Why does it keep happening?

Most often unstable tuning, a driver version with a bug for your card, heat, power delivery or unstable memory. Repeating timeouts at default settings with a clean driver point at the card.

Does turning off Issue Reporting fix it?

No. It only hides the pop-up.

Should I increase TdrDelay?

No. It is a debugging key; a longer delay hides the reset and leaves the hang.
